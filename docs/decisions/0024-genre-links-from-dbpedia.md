# 0024 ジャンルのつながりはDBpediaを優先する

- **日付**: 2026-10-16
- **決めたこと**: なりたち（0023）とノートのページで使うジャンルのつながりは、DBpedia（Wikipediaの情報欄をデータにしたもの）を優先する。
  - ジャンルのノートの前付けに、DBpediaの項目名を書く（`dbpedia = "House_music"`）。
  - `scripts/dbpedia_links.py`が、DBpediaのSPARQLの窓口から、ノートどうしのつながりだけを取ってきて`data/memo/dbpedia.json`に置く。読む性質は次の4つ。
    - `stylisticOrigin`（元になったジャンル）→ 源流（`src`）
    - `derivative`（派生したジャンル）→ 相手から見た源流
    - `musicFusionGenre`（混ざってできたジャンル）→ 相手から見た源流
    - `musicSubgenre`（下位のジャンル）→ 相手から見た上位（`up`）
  - `scripts/x_notes.py`がノートのつながりとまとめる。DBpediaがつないでいる2つのジャンルについては、ノートに書いたつながり（ざっとさんのデータなど）を使わない。DBpediaがつないでいない組み合わせは、ノートのつながりを残す。
  - なりたちの図では、源流（点線）はふだん隠し、ジャンルを指したときだけそのジャンルの分を出す。親子（実線）はいつも出す。
  - DBpediaのつながりを使ったページと、なりたちのページに「つながりの出典（一部）: DBpedia (Wikipedia, CC BY-SA)」と書く（初めは「つながりの一部」だったが、出典だと分かる固めの言い方にした）。
- **理由**:
  - 手で書いたつながりは、出典を確かめられなかった。DBpediaはWikipediaの情報欄から作られていて、どこから来たかをたどれる。
  - 1件ずつ項目のページを読む方法は、Jazzのような大きい項目で40秒以上かかった。SPARQLなら、要る性質だけを2回の問い合わせで取れる。
  - DBpediaのつながりを足すと線が113本から252本になり、点線で図が埋まった。そこで点線は指したときだけにした。
  - 別のジャンルの項目に転送される項目（Brostep → Dubstep、Kawaii Future Bass → Future bassなど）は、転送先のジャンルのつながりを横取りしてしまうので使わない。
- **守り方**:
  - データの更新は半自動（0004）。ジャンルのノートを足したときなどに手で回す。順番は`dbpedia_links.py` → `x_notes.py`。
  - DBpediaに問い合わせるときの名乗り（User-Agent）には、サイトのURLだけを入れる。メールアドレスなどは入れない。
  - DBpediaのデータはCC BY-SA。クレジットを消さない。
