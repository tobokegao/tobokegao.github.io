# 0031 メモの検索で、Xと同じfrom:やsince:を使えるようにする

- **日付**: 2026-10-19
- **決めたこと**: メモの検索の言葉から、`from:`、`to:`、`since:`、`until:`、`filter:media`／`retweets`／`replies`（`-`を付けると除く）を読み取る（`assets/js/notes.js`）。
  - 言葉があるときは、Pagefindで言葉を探し、見つかったポストを日付の行（「2025.01.02 03:04 RT @name」など）で絞る。
  - 言葉がなく、`from:`か`to:`があるときは、アカウントごとの小さな索引（`scripts/memo_query_index.py`、`/memo/q/`の256個のファイル、全部で約7.5MB）を読み、全部の年から探す。見つかったポストは、それぞれの月のページから読み込んで、20件ずつ出す。日付はポストの番号から割り出す（Xの番号は作られた時刻を持つ）。
  - `from:`に自分の名前だけを入れたときと、`since:`などだけのときは、言葉を足してもらう（自分のポストは約5万件あり、索引に入れると大きくなりすぎる）。
  - 絵の有無（`filter:media`）は、`from:`か`to:`と一緒のときだけ絞れる。
- **理由**:
  - Pagefindは月や話題のページを単位にしていて、ポスト1件ずつの「誰の」「いつの」を知らない。言葉なしの`from:`には答えられない。
  - ポスト1件ずつをページにする案は、0021と同じ理由（GitHub Pagesの1GB）でやめた。
  - 索引はActionsの組み立てで`data/memo`から作り、Gitには入れない。毎日の取り込み（0030）のたびに変わるので、入れると履歴がふくらむ（0022と同じ考え）。
- **守り方**:
  - メモの日付の行の書き方（`notes-post.html`）を変えたら、`notes.js`の読み取り方も直す。
  - 索引の形を変えたら、`memo_query_index.py`の説明と`notes.js`の`accountPosts`を両方直す。ファイルの分け方（FNV-1a）も2か所で同じにする。
