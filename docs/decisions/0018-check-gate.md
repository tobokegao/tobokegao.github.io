# 0018 決まりの点検をスクリプトにして、コミットと push の前に回す

- **日付**: 2026-10-01
- **決めたこと**:
  - `scripts/check.py` で、CLAUDE.md の決まりのうち機械で白黒をつけられるものを点検する。
  - 回す場所は 3 つ。
    - コミットの前（`.githooks/pre-commit`）: コミットに入れるファイルに関わる点検だけ
    - push の前（`.githooks/pre-push`）: 全部の点検と、Hugo での組み立て、組み立てたページのリンク
    - GitHub Actions（`site.yml` の Check）: 公開する前にもう一度
  - 結果は 2 種類。
    - NG: コミットや push を止める。わざと通すときは `--no-verify`。
    - 知らせ: 止めずに伝えるだけ。添削やスマホでの確認など、人の目で確かめる案内を、関わるファイルを変えたときに出す。
  - 点検するもの:
    - CSS: 色の直接指定、角丸、ぼかした影、グラデーション、斜体、ふわっと動く切り替え、ホバーで浮く動き、ch 単位や半端な px の余白、ドットフォントの大きさ、「視差効果を減らす」で止まらない動き
    - 言語と書き方: 日本語と英語の片方だけの文章、Markdown の書き間違い（CLAUDE.md の「間違えやすいところ」のうち機械で見つけられるもの）
    - 画像: WebP でない画像、大きすぎる画像
    - 2 か所にある同じ規則のずれ（二重実装）: ログの行の id、夜の光の段階色
    - その他: サイトに置いたジャケットのファイルの抜け、鍵やトークンらしき文字列、組み立てたページの行き先のないリンク、拡張子のない窓のタイトル
  - 「変えたら回すもの」と二重実装の一覧は、`check.py` の `REMINDERS`、`SAME_LINE`、`SAME_LIST` に置く。
- **理由**:
  - 見た目の決まりは細かく、目で探すと漏れが出る。初めて回したとき、記録の種類のチップに色の直接指定が見つかり、使われていない CSS も見つかった（どちらもこのとき直した）。
  - コミットの前だけだと、`--no-verify` で通したものや、手元に Hugo がないときの組み立ての確認が漏れる。そこで Actions でも止める。コミットの前で早く気づき、公開の前で確実に止める。
  - TRACKMENTO の `check.py` と同じ作り。
- **守り方**:
  - 作業の終わりの条件は「`python scripts/check.py --all` が通る」。
  - フックが動くようにするには、クローンごとに 1 回 `git config core.hooksPath .githooks` を動かす。
  - 網点など、意図があってあえて使う CSS は、その行に `check-ok: 理由` のコメントを書いて通す。理由のないまま通さない。
  - 2 か所に同じ規則を書いたときや、回し忘れると困るスクリプトを足したときは、`check.py` の一覧にも足す。
  - 斜体（`<em>`）は今は「知らせ」にとどめている。英語の作品名を斜体にするのは英語の書き方の慣習なので、強調かどうかは人が見る。
