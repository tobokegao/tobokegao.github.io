# 0009 読み込み先と権限をしぼる

- **日付**: 2026-09-30
- **決めたこと**:
  - ページにContent-Security-Policy（CSP）を`<meta>`で入れる（`layouts/_partials/head.html`）。スクリプトは自分のサイトのファイルと、最初に動く短いスクリプト（`assets/js/early.js`）だけ。画像は自分のサイトと、ジャケットを取ってくる5つのサービスの画像置き場だけ。フォントはGoogle Fontsだけ。
  - GitHub Actionsの部品は、版の名前ではなくコミットの番号で指定する。権限はワークフロー全体では何も渡さず、ジョブごとに必要なものだけ渡す。
  - データ更新のワークフローは、外のデータを読むジョブ（読むだけ）と、PRを作るジョブ（書き込みあり）に分ける。
  - 外から取ってくるリンクと画像は、サービスごとに決めた場所（httpsのみ）だけを受け付ける（`fetch_feeds.py`の`ALLOWED_HOSTS`、`collect_news.py`の`LINK_HOSTS`）。
  - 手元の振り分けツール（`review_x.py`）は、自分のページからの操作だけを受け付ける。
- **理由**:
  - 2026-09-30のセキュリティの点検で、鍵の漏れやXSSは見つからなかったが、部品や外のデータがおかしくなったときに被害が広がりやすい所がいくつかあった。
  - GitHub Pagesではレスポンスヘッダーを設定できないので、CSPは`<meta>`で入れる（`frame-ancestors`は使えない）。
  - アイコンの`style="--i:…"`があるので、スタイルは`'unsafe-inline'`を許している。クラスに置きかえれば外せる。
  - 最初に動くスクリプトはページに埋め込んだまま、中身のハッシュをCSPに書く。ファイルにしてHugoでハッシュを計算するので、中身を変えてもCSPを手で直す必要はない。
- **守り方**:
  - ジャケットの画像置き場を増やすときは、`fetch_feeds.py`の`ALLOWED_HOSTS`、`row_pics.py`の`PIC_HOSTS`、CSPの`img-src`をいっしょに直す（2026-09-30: ログの行の絵のためSpotifyの`i.scdn.co`を足した）。
  - 外部のスクリプトや、iframeの埋め込み（YouTubeなど）を足すとCSPに止められる。足すときはCSPも直し、この記録に書き足す。
  - Actionsの部品を新しくするときは、新しい版のコミット番号を調べ、番号とコメントの版を両方直す。
  - データ更新のPRは、自動でマージしない。中身を見てからマージする。
