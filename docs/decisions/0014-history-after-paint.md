# 0014 履歴に足すのは、新しいページが画面に出てから

- **日付**: 2026-10-01
- **決めたこと**:
  - ページを移るとき（0011）、`history.pushState` で履歴に 1 つ足すのを、新しい中身を画面に出したあと（次の画面が描かれてから）にする。タブの題名と説明も、そのときに変える。
  - そのあいだ、アドレスはまだ前のページのままなので、差し込む中身の相対的なリンクと画像の URL（プレビューのビルド）は、差し込む前に絶対の URL に直す。
  - 一度来たページや先に取ってあるページ（戻るボタンで戻る先もそう）は、待たずにその場で差し替える。メーターも出さない。
  - 戻るボタンで戻ったときのスクロールの位置は、ブラウザに任せず、離れるときに履歴の記録に書いておき、差し替えたあとに戻す（`history.scrollRestoration = "manual"`）。
  - 上のメニューと下のタブバーは差し替えずに残し、違うところ（いまのページの印、左上のロゴ、連絡先）だけを直す。押したリンクの「触れている」状態が消えないので、About の人形が回り続ける。
  - 先に取ったページは、最初の 6 枚の画像もすぐに読み込んで描く準備までしておき、その画像の要素を取っておく（夜昼で隠れている方のロゴは除く）。ページを移るときは、その 6 枚がそろうのを最大 0.3 秒待ち、取っておいた要素そのものを新しいページに差し込む。一瞬、画像のない状態が見えないようにするため。トップのページと、いま見ているページも先に取っておく。
- **理由**:
  - とぼけがおのスマホ（Android の Chrome）の普段のモードで、押してから真ん中の窓が変わるまでが遅かった。測ると、スクリプトが中身を用意し終えてから実際に画面に出るまでに、約 0.4 秒の待ちがあった。シークレットモードでは、この待ちはなかった。
  - 試しに `history.replaceState`（履歴を足さない）に替えると、普段のモードでも待ちが消えた。履歴を足すときに Chrome がする仕事（戻るジェスチャー用に画面を写すなど、と考えられる）が、次の画面を出すのを止めていた。
- **守り方**:
  - 戻るボタンで戻ったとき（`popstate`）は履歴を足さないので、すぐに題名を変える。
  - リンクや画像を持つ属性を `href` と `src` 以外にも使うなら、`site.js` の `swap()` で絶対の URL に直す対象に足す。
  - 履歴に足す前に別のリンクが押されても、足す処理はそのまま続ける。
