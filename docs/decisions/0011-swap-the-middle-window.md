# 0011 ページを移るときは真ん中の窓だけを差し替える

- **日付**: 2026-09-30
- **決めたこと**:
  - サイトの中のページへのリンクを押したら、`site.js` が次のページを取りにいき、`<main>`（真ん中の窓）と、上のメニュー、下のタブバーだけを差し替える。ページ全体は読み直さない。
  - 指やマウスがリンクに触れた時点で取りにいき始める。上のメニューや下のタブバーから開くページは、ブラウザの手が空いたときに先に取っておく。
  - 0010 の Speculation Rules はやめた（`speculation.json` と CSP のハッシュも消した）。読み込みメーターと、タイトル用フォントの先読みは残す。
- **理由**:
  - 0010 の先読みを入れても、とぼけがおのスマホ（Android の Chrome、プリロードの設定は標準、バッテリーセーバーはオフ）では、普段のモードでページの移動が遅いままだった。先読みはブラウザの判断で止まることがあり、Safari と Firefox では働かない。
  - 必要な中身だけを差し替えれば、ブラウザや設定に関係なく、画面をまっさらから描き直さずに済む。
- **守り方**:
  - ページの中で動く処理（ログの絞り込み、窓の開閉、リリースの絞り込みなど）は `site.js` の `initPage()` に書く。中身を差し替えるたびにこれを動かし直す。
  - メニューやタブバーの中のボタンは、差し替えで入れ替わるので、ボタンに直接イベントをつけず、ページ全体（document）でクリックを受け取る（言語と昼夜の切り替えがこの形）。
  - 別のサイト、ファイル（フィードや画像）、読み込みの失敗、古いブラウザでは、ふつうにページを読み込み直す。
  - 戻るボタンと URL は、ふつうのページと同じように動く（`history.pushState` と `popstate`）。
  - `<head>` で差し替えるのは、ページの題名と説明だけ。ページごとに CSS やスクリプトを変えるなら、この仕組みも直す。
  - 最初に開くページを軽くするため、本文のフォントの CSS（Google Fonts）は `early.js` から足し、画面を描くのを待たせない。ロゴは表示の大きさの WebP にし、隠れている昼夜の片方は読み込まない。リリースのカードは小さいジャケット（SoundCloud は 300px、Bandcamp は 350px）を使う。
