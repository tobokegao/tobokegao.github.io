# 0021 Xのアーカイブから、話題でつながるノートを作る

- **日付**: 2026-10-15
- **決めたこと**: Xのアーカイブにあるポストを全部（自分のポスト、他の人への返信、リツイート）、`/memo/`に載せ、話題ごとのページでつなぐ。`scripts/x_notes.py`がデータ（`data/memo/`）を作り、Hugoがページにする。検索はPagefindで、Hugoのあとに索引を作る。
  - ページの単位は話題。手で書くノート（`content/memo/*.md`）と、3回以上使ったハッシュタグが話題になる。
  - ノートには`[語]`でリンクを書く。向きのあるつながり（上位・下位・源流・影響先）は前付けに片側だけ書けば、反対側にも出る。`major = true`のノートは大ジャンルで、その下位のページがまとめて属する。
  - リツイートの全文は月ごとのページに載せ、そのページは検索エンジンに出さない（`noindex`）。話題のページには、だれのリツイートかと日付だけを出す。
  - 年表は、年のあるページを横に並べる。ジャンルの初めのデータとつながりは、ざっと（zatto）さんの音楽ジャンルWikiから、許可を得て取り込んだ（`scripts/notes_import_genres.py`）。0023で名前を「なりたち」（`/memo/roots/`）に変えた。
- **理由**:
  - ポスト1件を1ページにすると、5万ページを超え、共通の枠だけでGitHub Pagesの容量の目安（1GB）に近づく。話題と月のページにまとめれば、全部で650MBほどに収まる見込み（2019年分の実測から）。
  - リツイートは他の人のポストなので、転載の形はさけられない。とぼけがおが検索に使いたいので全文は載せるが、外の検索に出にくくして、元のポストへのリンクを付ける。
  - 本文の語から話題を拾うのはノートの名前だけにした。ハッシュタグ（#musicなど）まで本文から拾うと、ほとんどのポストがつながってしまった。
- **守り方**:
  - ノートを足したり名前を変えたりしたら、`python scripts/x_notes.py`を回す（`check.py`の知らせに入れた）。リンクとポストの一覧はそこで作り直す。
  - ノートの前付けはTOML（`+++`で囲む）。Pythonの標準のライブラリで読めるようにするため。
  - PagefindはWebAssemblyを使うので、CSPの`script-src`に`'wasm-unsafe-eval'`を足した。
  - 英語の表示用の文字（`[data-l="en"]`）は索引に入れない（`pagefind.yml`）。
  - ふつうの単語でもあるジャンル名（house、glitchなど）は、本文から拾わずハッシュタグだけで拾う（前付けの`tags`、または`match = "tags"`）。
  - アーカイブのハッシュタグから足したジャンルの年とつながりは、Claudeが一般の知識で下書きした。`unverified = true`の印を付け、ページに断り書きを出し、年表では点線の枠にする。とぼけがおが確かめたら印を外す。
  - 画像と動画はサイトに置き直さない（他の人の作品なので）。サムネイルだけを、Xのサーバー（`pbs.twimg.com`）から`360x360`（360pxに収まる大きさ）のWebPで読み、160pxの正方形に切って出す（最初は`thumb`の75pxだったが、小さすぎた。動画には`thumb`がない）。押すと元のポストを開く。元のポストが消えていたら「見られない」と出す（`site.js`）。Xで「センシティブな内容」の印が付いたポストは、サムネを出さず「画像あり」の印だけにする。CSPの`img-src`に`pbs.twimg.com`を足した。
  - メニューの名前は「メモ / Memo」（キーはM、F7）。アドレスも`/memo/`（窓は`C:\TBK\MEMO\`）。スクリプトやCSSの名前は`notes`のまま。
