# 0020 アーカイブより新しいポストは、URLから候補に足す

- **日付**: 2026-10-05
- **決めたこと**: これからの出演やリリースの告知は、ポストのURLを`work/x/inbox.txt`に1行書き、`x_urls.py`で読んで、アーカイブと同じ`work/x/candidates.json`に足す。そのあとは0006と同じく`review_x.py` → `x_to_timeline.py`。
- **理由**: アーカイブは頼んでから届くまで日がかかり、毎回数百GBある。XのAPIは有料で、ログインのCookieを使う方法（通知を受け続けるツールなど）は、アカウントを丸ごと動かせる鍵を手元に置くことになり、ずっと動かしておく必要もあるので、半自動の決まり（0004）に合わない。fxtwitterの公開API（`api.fxtwitter.com`）なら、鍵なしで1件ずつ本文と画像を取れる。
- **守り方**:
  - 点数と日付の読み取りは`import_x_archive.py`の`score`と`event_date`をそのまま使い、2か所に書かない。
  - ポストのidが同じなら、アーカイブとURLのどちらから来ても同じ候補になる。アーカイブを読み直しても、URLから足した候補（`source: x-url`）は残す。
  - fxtwitterは第三者のサービスで、止まることがある。そのときはURLの下に`> `で始まる行で本文を書けば、それを使う（画像なし、日付はその日）。
  - これから先の出来事は、日付が変わったり中止になったりする。ログに入れたあとも告知を見直す。
