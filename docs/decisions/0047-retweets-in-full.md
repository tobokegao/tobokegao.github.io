# 0047 アーカイブで途中までのリポストは、全文を読み直す

- **日付**: 2026-11-17
- **決めたこと**: Xのアーカイブで本文が途中までのリポストを、`scripts/x_rt_full.py`でfxtwitterから全文に読み直す。読めたものは全文を出し、名前のリンクを元のポストに向け、注記を外す。読めなかったもの（元のポストが消えた、非公開）には、注記「続きは保存されていません」を出す。
  - 「途中まで」の印は、本文が「…」で終わり、アーカイブの元の文が137字以上のリポストにだけ付ける（`x_notes.py`の`CUT_LEN`）。
  - 読み直した結果は`work/x/rt_full.json`に置く（Gitに入れない）。`x_notes.py`は、キャッシュ（`work/x/all_posts.json`）を書き換えずに、組み立てのたびにこれを重ねる。
- **理由**:
  - アーカイブは、リポストの本文を「RT @名前: 」を入れて140字までしか持っていない。それより長い本文は「…」で切れている。リポスト268,603件のうち、約8万件がこれに当たる。
  - 前の注記「アーカイブで途切れています」は、元のポストが消えたように読めた（2026-11-17）。
  - 前は「…」で終わるリポストすべてに印を付けていた。元の文がもともと「…」で終わるだけの短いリポスト（約3,100件）にも注記が出ていた。アーカイブの元の文の長さを測ると、切れたものは138〜140字に集まり、137字より短いものは切れていなかった。
  - fxtwitterにリポストの番号を渡すと、元のポストの全文と番号が返る。試した30件のうち29件が読め、1件は消えていた。
  - キャッシュを書き換えないのは、アーカイブを読み直してもやり直さずに済むようにするため。
- **守り方**:
  - 読み直しは1秒に1件より速くしない。約8万件で1日ほどかかった。fxtwitterの説明書きにある上限は、1つのIPアドレスから1分に1,000回（2026-11-17に確認）。1秒に1件はその6%なので、これより速くしない。`--limit`で分けて動かせる。途中で止めても、済んだ分は聞き直さない。
  - fxtwitterが「消えた」以外のエラーを返したポストは、飛ばして次の回に聞き直す。fxtwitterが動いていても、決まったポストでだけエラー（HTTP 500）になることがある（2026-11-18）。5回続けてエラーなら、スクリプトは止まる。間をおいて動かし直す。
  - 全文から拾うハッシュタグは、リンクの中の「#」を除き、100字までにする（`x_notes.py`の`HASHTAG`）。曲のデータを丸ごとアドレスに入れるリンクがあり、数千字の話題ができてHugoの組み立てが止まった（2026-11-19）。
  - 別の人のポストが返ってきたとき（名前も書き出しも違う）は、使わずに印を残す。
  - 終わったら`x_notes.py`を回す（`check.py`の知らせに出る）。
